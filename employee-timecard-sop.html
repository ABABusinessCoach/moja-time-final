Timecard Process Flow

Moja Behavioral Services - Time Tracking System

Internal Process Document
Generate Timecards → Employee Review → Notes & Corrections → Admin Review → Final Approval + Email

Stage 1: Timecard Generation

Triggers

  • Automatic (Cron): Runs every other Friday at 3:00 PM EST on the last day of the pay period
  • Manual: Admin clicks "Send Manual Timecards" from the admin panel at any time

Pay Period Structure

  • Duration: Bi-weekly (14 days)
  • Starts: Saturday
  • Ends: Friday
  • Overtime: Calculated per week (>40h)

What the System Does

  • Retrieves all active staff members
  • Pulls all clock logs for the 2-week pay period
  • Calculates gross hours per shift (clock in to clock out)
  • All breaks are paid and included in total hours
  • Calculates overtime: any hours exceeding 40 per week
  • Creates a timecard report record for each employee
  • Sends an email to each employee with their timecard summary and a review link
Deadline: Employees must review and respond by 8:00 PM EST on the day the timecard is sent. After this deadline, timecards without notes auto-approve.

Stage 2: Employee Review

How Employees Access

  • Click the link in their email (token-based, no login required)
  • Or enter their 4-digit PIN on the "My Hours" page

Actions Available to Employees

Action Description Effect on Status
View Timecard See full 2-week breakdown with daily shifts, breaks, regular/OT hours No change
Add Note Flag an issue on a specific shift or leave a general note Changes to "Has Notes"
Propose Correction Request a time change (new clock in/out) or override total hours for a shift Changes to "Has Notes"
Approve Confirm the timecard is accurate as-is Changes to "Employee Approved"
No Action (by 8 PM) If no notes/corrections exist, auto-approves at deadline Auto-changes to "Employee Approved"
Note: Employees can edit or delete their own notes and withdraw pending corrections before admin reviews them.

Stage 3: Admin Review & Processing

Admin Dashboard View

The admin sees two tabs: "Needs Review" (pending timecards) and "Approved" (finalized). Each card shows employee name, total hours, OT, shift count, and whether they are currently clocked in (live indicator).

Admin Actions

Respond to Employee Notes
For each open note, admin can Resolve (with comment) or Dismiss. Once all notes are resolved, report progresses.
Approve or Reject Correction Requests
Approve: Applies the employee's proposed times and recalculates hours.
Reject: Keeps original times; optionally provides a reason visible to employee.
Direct Shift Override (Admin Edit)
Admin can edit any shift regardless of status: modify clock in/out and break times. Changes take effect immediately and hours recalculate.
Final Approval
Admin clicks "Approve & Send Email" to finalize the timecard and send confirmed hours to employee.

Admin Edit Capabilities

Important: Admin can edit timecards at any stage, including after employee approval or even after full admin approval. There are no restrictions on admin editing power.

Stage 4: Final Approval & Email

What Happens When Admin Approves

  • Report status changes to "Approved"
  • Admin approval timestamp and admin ID are recorded
  • System builds final timecard with all approved corrections applied
  • A Final Hours Confirmation Email is sent to the employee containing:
    • Confirmation banner: "Your timecard has been approved!"
    • Final total hours (regular + overtime)
    • Full day-by-day breakdown with all corrections reflected

Stage 5: Post-Approval

  • Employee can still view the finalized timecard (read-only)
  • Admin can still make edits if needed (e.g., payroll correction discovered later)
  • All changes are tracked in the audit log

Status Reference

Common Scenarios

Scenario A: No Issues (Happy Path)

Generated (Fri 3 PM) → Auto-Approve (8 PM) → Admin Final Approve

Employee takes no action; timecard auto-approves at deadline. Admin reviews and clicks approve.

Scenario B: Employee Flags an Issue

Generated → Employee Adds Note → Admin Resolves → Admin Approves

Employee notices a discrepancy, adds a note. Admin reads and resolves it, then finalizes.

Scenario C: Employee Requests Time Correction

Generated → Correction Proposed → Admin Approves/Rejects → Final Approve

Employee proposes new clock in/out times for a shift. Admin evaluates and approves or rejects, then finalizes.

Scenario D: Admin Overrides Directly

Any Status → Admin Edits Shift → Hours Recalculated → Admin Approves

Admin proactively edits shift times without waiting for employee input. Can be done at any stage.

Auto Clock-Out Protection

Shifts that exceed the configured maximum (default: 16 hours) are automatically capped to prevent forgotten punches from inflating hours:

  • At clock-in: If a stale shift is still open, it's auto-closed at the 16h mark before the new shift starts
  • At clock-out: Duration is capped at 16h if elapsed time exceeds it
  • Hourly cron: Proactively closes any shift open longer than 16h
